Here is the high-level pseudocode for a Shared-Subspace Multi-Heuristic A* (MHA*)solver.

To keep it clean, we use Queue 0 as the strict Anchor and Queue 1 as the greedy Scout. The key trick is that both queues share a single closed_list to prevent duplicate expansions, but each node tracks its own path cost (g) independently inside each queue's context.
The MHA* Pseudocode

class Node:
    state        # The current grid configuration
    parent       # Pointer to parent node
    g            # Cost to reach this node (number of steps)

function solve_6x6_puzzle(start_state):
    # 1. Initialize the shared closed list (Transposition Table)
    # Stores the best g-value seen for any state to prevent redundant work
    closed_list = HashMap() # Key: state_hash, Value: integer_g

    # 2. Initialize the two Open Lists (Priority Queues)
    anchor_open = PriorityQueue()  # Sorted by: g + (1.0 * anchor_h)
    scout_open  = PriorityQueue()   # Sorted by: g + (w * scout_h)

    # 3. Create and insert the root node
    root = Node(state=start_state, parent=None, g=0)
    
    anchor_open.insert(root, priority = 0 + (1.0 * calc_anchor_h(start_state)))
    scout_open.insert(root,  priority = 0 + (w * calc_scout_h(start_state)))
    closed_list.set(hash(start_state), 0)

    # 4. Set the duty cycle (e.g., expand 4 scout nodes for every 1 anchor node)
    scout_bias = 4
    counter = 0

    # 5. Main Search Loop
    while not anchor_open.is_empty() and not scout_open.is_empty():
        
        # Decide which queue to expand from (Round-Robin with bias)
        if counter % (scout_bias + 1) == 0:
            current_node = anchor_open.pop_best()
            current_queue = "anchor"
        else:
            current_node = scout_open.pop_best()
            current_queue = "scout"
            
        counter += 1

        # Check if we reached the goal
        if is_goal(current_node.state):
            return reconstruct_path(current_node)

        # If this state was already closed via a cheaper path, skip it
        if closed_list.get(hash(current_node.state)) < current_node.g:
            continue

        # Mark this state as expanded at this g-cost
        closed_list.set(hash(current_node.state), current_node.g)

        # 6. Expand Child Nodes
        for move in get_valid_moves(current_node.state):
            child_state = execute_move(current_node.state, move)
            child_g = current_node.g + 1

            # Duplicate detection using the shared closed list
            if closed_list.has(hash(child_state)) and closed_list.get(hash(child_state)) <= child_g:
                continue # A better or equal path to this state already exists

            # Create the child node
            child_node = Node(state=child_state, parent=current_node, g=child_g)

            # Calculate separate priorities for each queue
            # Anchor uses your clean, unweighted Linear Conflict heuristic
            h_anchor = calc_anchor_h(child_state)
            p_anchor = child_g + (1.0 * h_anchor)
            
            # Scout uses your inflated weight + optional structural penalties
            h_scout = calc_scout_h(child_state) 
            p_scout = child_g + (w * h_scout)

            # Insert the exact same child node into both queues
            anchor_open.insert(child_node, priority=p_anchor)
            scout_open.insert(child_node, priority=p_scout)

    return "No Solution" # Should not happen for valid puzzle states

The Shared closed_list Guard:
When the scout queue goes running down a bad, cyclic path, its path cost (g) climbs very high. If it loops back into an area the anchor already solved cleanly, the line closed_list.get(hash(child_state)) <= child_g instantly kills the scout's messy branch before it can clutter your queues.
The "Memory Bypass" Pop:
Notice that when a node is popped, we double-check if closed_list.get(...) < current_node.g. Because the node exists in both queues, when the Anchor queue pops and processes a node, that same state might still be sitting deep inside the Scout queue. This check ensures that when the Scout queue eventually encounters that duplicate later, it discards it instantly in O(1) time without wasting CPU cycles re-expanding it.
Tuning the scout_bias:
Setting scout_bias = 4 means your program spends 80% of its energy sprinting toward the goal using the heavy weight. If the scout makes a blunder, the remaining 20% of the cycles given to the anchor queue will automatically step in and pull the search back onto the mathematically correct track.
